# Testing Standards

## Overview

Heavy unit testing on pure puzzle logic; light component tests on key UI flows.

## Testing Framework

**Framework**: Vitest
**Runner**: Vitest (jsdom environment for components)

## Test Types

| Type | Tool | Location | When to Use |
|------|------|----------|-------------|
| Unit | Vitest | `src/**/*.test.ts` | All puzzle logic (generation, placement, validation) |
| Component | Vitest + Testing Library | `src/**/*.test.tsx` | Key user flows (enter words, generate, resize) |
| Manual | Chrome on Android | — | PWA install + offline check per release |

## Coverage Requirements

**Target**: 80% on `src/puzzles/*/logic`
**Enforcement**: Advisory (reported, not blocking)

**Critical paths that MUST have coverage:**
- Word placement (all words placed, within bounds, overlaps only on matching letters)
- Input validation (too-long words, empty input, non-letters)
- Grid size limits

## Test Naming

**Pattern**: `describe('<unit>') > it('<behaviour in plain English>')`

**Examples**:
- `it('places every word inside the grid')` — placement correctness
- `it('rejects a word longer than the grid')` — validation

## Test Structure

```typescript
describe('generateGrid', () => {
  it('places every word inside the grid', () => {
    const rng = seededRandom(42);
    const result = generateGrid(['KAT', 'HOND'], { width: 8, height: 8 }, rng);
    expect(result.ok).toBe(true);
  });
});
```

## Mock Strategy

**Approach**: Minimal — inject dependencies (RNG) instead of mocking

**Guidelines**:
- Use a seeded RNG for deterministic tests
- Mock `localStorage` only via jsdom's built-in implementation

## Test Data

**Strategy**: Inline small word lists in tests

**Guidelines**:
- Include Dutch words with IJ, diacritics (é, ë) to test normalization

## Running Tests

```bash
# Run all tests
npm test

# Run with coverage
npm run test:coverage

# Run specific test file
npx vitest run src/puzzles/woordzoeker/logic/generateGrid.test.ts

# Run in watch mode
npx vitest
```
