## Naming Conventions

### Variables and Functions

| Element | Convention | Example |
|---------|------------|---------|
| Variables / functions | camelCase | `placeWords` |
| React components | PascalCase | `WordSearchGrid` |
| Types / interfaces | PascalCase | `GridOptions` |
| Constants | UPPER_SNAKE_CASE | `MAX_GRID_SIZE` |

### Files and Folders

- **Components**: PascalCase (e.g., `WordSearchGrid.tsx`)
- **Logic / utils**: camelCase (e.g., `generateGrid.ts`)
- **Tests**: next to source (e.g., `generateGrid.test.ts`)
- **Puzzle features**: one folder per puzzle (e.g., `src/puzzles/woordzoeker/`)

## File Organization

### Project Structure

```
src/
├── app/            # App shell, routing, layout
├── puzzles/
│   └── woordzoeker/
│       ├── logic/      # Pure TS: grid generation, placement
│       ├── components/ # React UI
│       └── data/       # Theme word lists (Dutch)
├── shared/         # Reusable components, hooks, storage helpers
└── main.tsx
```

### Conventions

- **Puzzle logic**: pure functions, no React/DOM imports, deterministic when given a seeded RNG
- **UI text**: Dutch, kept in components (or a `texts.ts` per feature if it grows)


**Rules**:
- External, then internal (`@/`), then relative; blank line between groups

## Error Handling

### Pattern

**Approach**: Return result objects from logic (`{ ok: true, grid } | { ok: false, reason }`); UI shows a Dutch message.

### Guidelines

- Validate user input (word length vs. grid size, invalid characters) before generating
- Never throw for expected failures (e.g. word doesn't fit)

### Example

```typescript
const result = generateGrid(words, options);
if (!result.ok) {
  setError(result.reason); // e.g. "Het woord 'OLIFANT' past niet in een 5×5 raster."
}
```

## Comments and Documentation

### When to Comment

- Explain *why* for non-obvious algorithms (placement, retry strategy)
- No comments restating the code

### Documentation Format

**Functions**: TSDoc on exported logic functions
**Classes**: n/a (prefer functions)

## Code Patterns

### Preferred Patterns

#### Pure logic + seeded RNG

Puzzle generation takes an injectable random function so tests are deterministic.

```typescript
export function generateGrid(words: string[], opts: GridOptions, rng: () => number = Math.random) { /* ... */ }
```

### Anti-Patterns to Avoid

- **Logic inside components**: hard to test; move to `logic/`
- **`any`**: hides bugs
- **Hardcoded English UI strings**: UI must be Dutch
