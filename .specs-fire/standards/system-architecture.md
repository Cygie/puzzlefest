# System Architecture

## Overview

PuzzleFest is a static, client-only PWA hosting a growing collection of Dutch puzzles. Each puzzle is a self-contained feature module. Woordzoeker is the first.

## System Context

Runs entirely in the user's browser (primarily Chrome on Android, installed to the home screen). No server-side logic; served as static files.

### Context Diagram

```
[Gebruiker (Android/desktop)] --> [PuzzleFest PWA in browser]
                                        |
                                  [localStorage]  [Service worker cache]
```

### Users

- **Speler / maker**: Dutch-speaking user who creates and solves word searches on their phone, possibly prints them

### External Systems

- **Static host**: serves the built files (TBD)

## Architecture Pattern

**Pattern**: Modular SPA (feature folders per puzzle)
**Rationale**: Simple, offline-capable, easy to add new puzzle types.

## Component Architecture

### Components

#### App shell

- **Purpose**: Layout, navigation between puzzles, PWA install prompt
- **Responsibilities**: Routing, header/menu
- **Dependencies**: React

#### Woordzoeker module

- **Purpose**: Generate and play word searches
- **Responsibilities**: Theme selection, word entry, width/height settings, grid generation, display/solving
- **Dependencies**: Shared UI, theme word list data

#### Shared

- **Purpose**: Reusable UI and helpers
- **Responsibilities**: Buttons, inputs, storage helper, RNG
- **Dependencies**: none

### Component Diagram

```
App shell
 └── Woordzoeker
      ├── Settings (thema, woorden, breedte, hoogte)
      ├── logic/generateGrid (pure TS)
      └── Grid view
```

## Data Flow

User picks a theme and/or enters words, sets width/height → logic normalizes words and generates a grid → UI renders the grid and word list → state optionally persisted to localStorage.

```
Input -> normalize -> generateGrid -> render -> (save to localStorage)
```

## Technology Stack

| Layer | Technology | Purpose |
|-------|------------|---------|
| UI | React + TypeScript | Components |
| Build | Vite | Dev server, bundling |
| PWA | vite-plugin-pwa | Manifest, offline service worker |
| Storage | localStorage | Settings, saved puzzles |
| Tests | Vitest + Testing Library | Unit/component tests |

## Non-Functional Requirements

### Performance

- **Grid generation**: < 200 ms for a 20×20 grid with 20 words on a mid-range phone
- **First load**: < 2 s on 4G; instant when installed (offline cache)

### Security

- No external network calls at runtime
- No personal data collected

### Scalability

Static hosting; scales trivially.

## Constraints

- UI fully in Dutch
- Must work offline once installed
- Touch-first UI usable on small screens
- Dev machine is a Raspberry Pi 5 — keep tooling lightweight

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| App delivery | PWA (Capacitor later if Play Store needed) | No Android SDK needed; installable from browser |
| Theme words | Bundled Dutch word lists | Offline, free, predictable |
| Backend | None | Not needed for v1 |
