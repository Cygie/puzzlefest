# Implementation Walkthrough: Hash routes for Woordzoeker screens

## Summary

Every Woordzoeker screen now has its own address, so the Android back button (and browser back/forward) moves between screens instead of leaving the page. Saved puzzles also survive a reload.

## Key Implementation Details

### 1. Routes

| Address | Screen |
|---|---|
| `#/woordzoeker` | Setup |
| `#/woordzoeker/mijn` | Mijn puzzels |
| `#/woordzoeker/spel` | Unsaved puzzle (memory) |
| `#/woordzoeker/spel/<id>` | Saved puzzle (storage) |

### 2. Saving without restart

Opslaan stores the puzzle, marks the memory puzzle as saved and replaces the address with `/spel/<id>`; the PlayScreen keeps its key, so the game simply continues.

### 3. Redirects

`/spel` without a puzzle → setup (replace); unknown `/spel/<id>` → Mijn puzzels with "Deze puzzel is niet (meer) opgeslagen op dit apparaat."

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Navigation model | Hash route per screen | History drives the back button; works on static hosts and in the PWA |
| Saving | Replace URL, keep play screen mounted | No extra history entry; no restart |
| Unsaved progress on back/forward | Kept in page memory | Going back and forward resumes the game |
